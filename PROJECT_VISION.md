# Space Miner - Project Vision

## Overview

Space Miner is a factory automation and incremental strategy game inspired by:

- Factorio
- Dyson Sphere Program
- Satisfactory
- Shapez 2
- No Man's Sky

The player starts with a tiny mining headquarters orbiting Earth and slowly expands into an industrial civilization spanning planets, solar systems, galaxies, and eventually an infinite procedurally generated universe.

This is **not** a traditional idle game where numbers simply increase. Progress comes from solving increasingly complex logistics and automation challenges.

# Design Philosophy

Every new system should create interesting logistical problems.

Players should spend more time designing efficient production networks than clicking buttons.

Automation should always replace manual work.

The game should always feel alive.

Every object should:

- Move
- React
- Connect to something
- Or visually evolve

Avoid static worlds.

# Coding Guidelines

When making changes:

- Read the project first.
- Preserve existing architecture.
- Keep systems modular.
- Avoid duplicated code.
- Prefer reusable classes.
- Comment major systems.
- Keep files focused on one responsibility.
- Make changes in small working commits.
- Never rewrite large portions of the project unless necessary.

---

# Gameplay Philosophy

The player should always feel like they are building a living industrial civilization.

Early Game:
One mine.

Mid Game:
A thriving orbital factory around Earth.

Late Game:
An industrialized planet with cargo moving everywhere.

End Game:
Thousands of automated factories spanning countless star systems.

Watching the factory operate should be satisfying even when the player does nothing.

# AI Instructions

Before implementing new features:

1. Understand the existing architecture.
2. Reuse existing systems whenever possible.
3. Avoid unnecessary rewrites.
4. Keep the game playable after every change.
5. Prioritize maintainability over quick hacks.
6. Build systems that can scale to hundreds or thousands of buildings.
7. If multiple implementation options exist, choose the one that is easiest to extend in the future.

The goal is to create a polished automation game that feels alive, scales infinitely, and rewards players for building increasingly efficient logistics networks.
